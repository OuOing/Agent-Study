# 术语速查：Agent 开发核心概念

这一页作为章节笔记的速查表。后续正式复习时，只需要从 `README.md` 进入 `chapters/`。

## 大语言模型 LLM

能够根据上下文生成和理解文本的模型。它本身通常只产生内容，不直接访问数据库或执行系统操作。

## Prompt

发送给模型的指令和上下文，包括角色、任务、约束、示例和用户输入。Prompt 是模型的输入设计，不等于完整的业务逻辑。

## 上下文 Context

模型本次调用时能够看到的信息，例如最近对话、用户资料、检索到的文档和工具结果。上下文越多不一定越好，需要控制相关性和长度。

## 工具 Tool

应用程序暴露给模型的一项可调用能力。模型只生成工具名和参数，真正执行由后端完成。

## Tool Calling

模型以结构化格式请求调用工具的机制。后端校验请求、执行函数，再将结果返回模型。

## 编排器 Orchestrator

负责协调模型、工具和状态的后端逻辑。它决定调用顺序、异常处理、循环上限和人工审批。

## 状态 State

任务当前进度及其数据，例如 `awaiting_approval`、已执行的工具和中间结果。状态用于暂停、恢复和审计任务。

## 记忆 Memory

跨多次对话保存的信息，例如用户偏好。记忆不是完整聊天记录，也不应未经控制地保存所有内容。

## RAG

Retrieval-Augmented Generation，即检索增强生成。先从外部知识库检索相关资料，再把资料交给模型生成回答。

## 结构化输出 Structured Output

要求模型按照指定 JSON 或 Schema 输出。它让后端可以可靠地读取字段，而不是从自由文本中猜意思。

## 编排循环

Agent 反复执行“模型决策 -> 工具行动 -> 观察结果”，直到完成、失败或交给人工。
