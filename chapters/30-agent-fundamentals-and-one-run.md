# 第三十章：基础回补——Agent 的组成与一次完整运行

前面几章讨论了幂等、对账和失败恢复。这些是 Agent 真正接入外部系统后必须考虑的工程问题，但学习时若直接从这些故障切入，很容易忘记主干。本章先把最基本的运行方式说清楚，再把复杂问题放回它们所属的位置。

## 1. Agent 是什么

在本课程里，Agent 指一个围绕目标反复运行的应用：模型根据输入和当前信息提出下一步，应用可以调用被允许的工具，把结果交回模型，直到形成最终答案或触及停止条件。模型是重要部件，但 Agent 不只是模型，也不只是提示词。

普通的单轮问答可以是“给模型一句话，得到一段文字”。Agent 多了“根据中间结果继续行动”的能力。例如：用户要从会议记录里整理待办，Agent 可以先检索记录，再根据检索结果写出待办。是否需要更多工具调用，由编排逻辑约束，不能无限循环。

OpenAI Docs 对 Agent 运行循环的描述同样是：调用模型、检查输出、执行工具调用或交接、继续，最后返回答案。不同产品或 SDK 的实现细节可以不同，循环思想相通：<https://developers.openai.com/api/docs/guides/agents/running-agents>。

## 2. 五个基本部件

**目标与输入**：用户要完成什么，例如“找出周会提到的风险，并整理待办”。目标不是工具命令，它还需要被解释和分解。

**模型**：负责根据当前上下文提出决策。在本项目中，`Model.Decide` 返回 `Decision`：要么 `tool_call`，要么 `final`。模型提出动作，不直接拥有数据库或支付权限。

**工具**：应用暴露的具体能力，例如 `search_notes`。模型返回工具名和参数后，由后端找到工具、校验参数并执行。工具可以只是读取，也可以有外部副作用；这一区别决定之后是否需要审批、幂等和对账。

**编排器**：控制运行循环，决定何时调用模型、何时执行工具、何时停止。在本项目中是 `Orchestrator.Run`，它还设置最大步数，防止无休止的模型—工具循环。

**上下文与状态**：上下文是这一次模型调用能看到的材料；状态是应用为了继续、恢复、审计而保存的任务事实。两者相关但不相同。当前 `Orchestrator.Run` 只把上一步工具结果放进 `observation`，并未实现完整对话历史或跨重启的执行检查点。

## 3. 沿着项目代码走一遍

项目的 `DemoModel` 和 `SearchNotesTool` 展示了最小闭环：

```text
用户目标：根据会议记录整理待办
  → Orchestrator 调用 Model.Decide
  → DemoModel 返回 tool_call: search_notes({query: "会议记录"})
  → Registry 找到 SearchNotesTool 并执行
  → 工具返回 matches，成为下一轮 observation
  → Orchestrator 再次调用 Model.Decide
  → DemoModel 返回 final，运行结束
```

这里的 `DemoModel` 按固定规则演示流程，不会像真实模型那样理解会议内容并生成精细待办。这个例子教的是架构分工，不是模型能力。

## 4. 四组常被混淆的东西

**工具请求与工具执行**：模型说“调用 `search_notes`”只是请求。真正执行的是后端。后端必须决定工具是否存在、参数是否合法、用户是否有权调用。

**工具结果与最终答案**：`search_notes` 返回的是资料，不一定能直接呈现给用户。模型可能还要根据资料整理、解释或决定下一步。

**上下文与持久状态**：`observation` 可以让下一轮模型看到工具结果，但进程结束后它就没了。任务是否完成、哪个操作已扣款等事实需要独立保存；不能把“模型可能记得”当成持久化。

**任务失败与外部动作失败**：第 29 章的扣款例子说明，Worker 返回错误，不等于外部扣款失败。应用状态和外部业务事实必须分别核对。

## 5. 基础能力如何长成工程系统

最小闭环只需模型、工具和循环；接入真实业务后，才逐层增加限制：输入/工具参数校验、步骤和时间上限、日志、任务持久化、审批、幂等与对账。这些不是另一套与 Agent 无关的知识，而是围绕同一个运行循环保护数据和用户。

本项目目前的 `Orchestrator` 会直接通过 `Registry.Execute` 调用工具。第 28～29 章的内存幂等执行器是独立原型，尚未接进主流程，也不适合直接保护真实写操作。

## 6. 一句话记住

模型负责**提出下一步**，工具负责**接触外部世界**，编排器负责**控制循环**，应用状态负责**记住已经发生的事**。先看清这四种职责，再学习重试、幂等或多 Agent，就能知道每个机制要解决哪一类问题。
