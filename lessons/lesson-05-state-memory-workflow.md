# 第 5 课：状态、记忆与工作流

## 为什么需要这三个概念

一次简单问答可以只依赖当前上下文，但“分析资料、生成草稿、等待确认、执行写入”这类任务会跨越多个步骤，甚至跨越多次请求。系统需要知道任务进行到了哪里，也需要决定哪些信息应该长期保留。

## 什么是对话历史

对话历史是用户和模型之前说过的话。例如：

```text
用户：帮我整理会议
助手：我找到了会议记录
用户：只保留行动项
```

它主要用于帮助模型理解当前对话，不等同于任务进度，也不等同于长期记忆。

## 什么是状态

状态表示任务当前处于哪个阶段，以及已经产生了哪些结果。例如会议助理可以有：

```text
created
-> reading_notes
-> draft_ready
-> awaiting_approval
-> executing
-> completed
```

状态应保存在数据库或可靠的任务存储中。服务重启后，系统可以根据状态继续，而不是从头猜测。

## 什么是记忆

记忆是跨会话保留的信息，例如用户喜欢简洁回答、负责某个部门，或者某个项目的固定背景。

记忆应该有明确的写入规则、来源和删除机制。不是所有聊天内容都值得保存，也不能未经允许保存敏感信息。

## 三者的区别

| 概念 | 主要回答的问题 | 例子 |
|---|---|---|
| 对话历史 | 我们之前说了什么？ | 最近十轮对话 |
| 任务状态 | 这项工作做到哪一步？ | 等待用户确认 |
| 长期记忆 | 未来还需要知道什么？ | 用户偏好简洁回答 |

## 什么是工作流

工作流是预先设计的步骤和条件。例如报销流程：

```text
提交申请 -> 校验金额 -> 部门审批 -> 财务审批 -> 打款
```

步骤、权限和状态转换由代码定义，因此容易测试和审计。

## 什么是 Agent 循环

Agent 循环允许模型根据当前结果决定下一步：

```text
模型判断 -> 调工具 -> 观察结果 -> 模型再次判断
```

它适合路径不完全确定的任务，例如研究问题、排查故障和跨系统查找资料。

## 工作流和 Agent 如何配合

实际系统通常不是二选一，而是：

```text
确定的业务骨架：工作流
不确定的局部判断：Agent
```

例如合同处理工作流固定为“上传、解析、审批、归档”，但“从合同中找出风险条款”可以交给模型。

## 什么是检查点

检查点是任务执行过程中保存的可恢复位置。例如工具调用成功后保存：

```text
任务 ID
当前状态
已完成步骤
工具结果
下一步计划
```

服务重启后从最后一个检查点继续，可以避免重复执行有副作用的操作。

## 为什么状态转换必须由代码控制

模型可以建议“现在应该发送邮件”，但不能自行把状态从 `awaiting_approval` 改成 `completed`。系统应该检查用户是否确认、邮件是否真的发送成功，再由代码更新状态。

## 复习摘要

- 对话历史记录交流内容，状态记录任务进度，记忆保存跨会话信息。
- 工作流适合固定步骤，Agent 适合不确定判断。
- 稳定的企业 Agent 通常使用“工作流骨架 + Agent 局部决策”。
- 检查点、状态转换和幂等设计决定任务能否安全恢复。
