# 第 6 课：前后端集成与流式交互

## 1. 为什么 Agent 需要前端

Agent 任务可能持续几秒甚至几分钟。用户不仅需要最终答案，还需要知道系统正在做什么、是否失败、是否需要确认。因此前端要展示任务状态、工具调用和人工审批。

## 2. 前端和后端的职责

前端负责：

- 收集用户目标
- 展示消息和任务进度
- 展示工具执行结果
- 处理确认、取消和重试

后端负责：

- 用户认证和权限
- 调用模型和工具
- 保存对话与任务状态
- 控制重试、超时和审批

模型密钥和工具权限不能放在前端。

## 3. HTTP 请求是什么

HTTP 是浏览器和后端通信的基础协议。最简单的 Agent 接口可以是：

```text
POST /api/tasks
请求：用户目标
响应：任务 ID
```

后端立即返回任务 ID，表示任务已经创建，而不是让浏览器长时间等待完整结果。

## 4. 异步任务是什么

异步任务是“先创建，后处理”。后端收到请求后把任务放入执行队列，由后台 worker 调用模型和工具。

这样可以处理长任务、服务重启和失败重试。数据库中会保存：

```text
task_id
user_id
status
current_step
result
error
created_at
updated_at
```

## 5. SSE 是什么

SSE（Server-Sent Events）允许后端通过一个持续的 HTTP 连接，把事件不断推送给浏览器。它适合单向的实时更新：服务器告诉前端任务进度。

事件可能是：

```text
task.started
tool.started
tool.completed
approval.required
task.completed
task.failed
```

前端收到事件后更新界面。SSE 比定时轮询更及时，也比双向通信更简单。

## 6. WebSocket 是什么

WebSocket 建立一个双向持续连接，浏览器和服务器都可以随时发送消息。它适合实时协作、语音交互和需要频繁双向通信的应用。

如果只是后端向前端推送 Agent 进度，SSE 往往已经足够；不应为了“实时”默认使用更复杂的方案。

## 7. 流式输出是什么

流式输出是模型生成一部分，后端就转发一部分，而不是等完整答案生成后再返回。

用户体验通常是：

```text
正在分析...
正在查询资料...
已找到 3 条相关内容
正在生成回答...
```

流式输出不只传文字，也应该传结构化事件，让前端知道当前是文本、工具调用、审批还是错误。

## 8. 人工确认界面

高风险动作不能只显示一句“即将执行”，而应该展示清楚：

- 要执行什么动作
- 目标对象是谁
- 使用哪些参数
- 可能产生什么影响
- 确认和取消按钮

用户点击确认后，后端仍需再次检查权限和任务状态，不能只相信前端传来的“确认”。

## 9. 认证和权限

认证回答“你是谁”，权限回答“你能做什么”。

例如用户已登录不代表他有权查看所有合同。每次工具执行前，后端都应根据服务器端的用户身份重新判断权限。

## 10. 一个完整的前后端流程

```text
前端 POST 创建任务
 -> 后端认证并保存任务
 -> 返回 task_id
 -> worker 执行 Agent
 -> SSE 推送进度
 -> 需要审批时暂停
 -> 前端 POST 确认
 -> 后端验证后继续执行
 -> 推送 completed 和最终结果
```

## 复习摘要

- 前端展示任务，后端掌控模型、工具和权限。
- 长任务适合“创建任务 + 后台执行 + 状态推送”。
- SSE 适合服务器单向推送进度，WebSocket 适合双向实时通信。
- 前端确认只是用户意图，后端必须再次校验。
