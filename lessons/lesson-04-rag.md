# 第 4 课：RAG 与知识库

## RAG 是什么

RAG 是 Retrieval-Augmented Generation，中文通常译为“检索增强生成”。它不是重新训练模型，而是在回答前先找到相关资料，再把资料交给模型。

```text
用户问题
 -> 检索相关资料
 -> 把资料放入上下文
 -> 模型基于资料生成回答
```

## 为什么需要 RAG

模型训练完成后，不会自动知道你的公司制度、内部项目或最新数据。直接询问模型可能得到过时或编造的答案。

RAG 让模型在回答时读取外部资料，因此适合企业知识库、产品文档、客服资料和内部制度。

## 什么是知识库

知识库是可以被系统存储和检索的资料集合，包括 PDF、网页、数据库记录、Markdown、FAQ 和产品文档。

知识库不仅是文件夹，还需要保存每段内容的来源、标题、权限、更新时间和所属业务对象。

## 什么是文档切分

模型和检索系统不适合每次读取整本长文档，所以要把文档拆成较小的片段。每个片段应该尽量表达一个完整主题。

切得太大：检索不够精确，上下文浪费。切得太小：语义不完整，模型缺少上下文。实际项目通常按标题、段落和语义边界切分，并保留少量重叠。

## 什么是 Embedding

Embedding 是把一段文字转换成一串数字。语义相近的文字，转换后的数字通常也更接近。

例如：

```text
“如何申请年假”
“年假审批流程是什么”
```

虽然字面不同，但语义接近，Embedding 可以帮助系统发现它们相关。

## 什么是向量

向量就是一组数字。Embedding 产生的向量可以被保存，并用距离计算相似度。

向量数据库负责保存这些向量，并快速找到与用户问题最相似的文档片段。常见实现可以基于 PostgreSQL 扩展或专用向量数据库。

## 什么是检索

检索就是从知识库中找出可能回答问题的片段。常见方式有：

- 关键词检索：匹配具体词语，适合产品编号和专有名词
- 向量检索：匹配语义，适合表达方式不同但意思相近的问题
- 混合检索：结合关键词和向量，通常更稳健

## 什么是重排

第一次检索可能找出几十个候选片段。重排模型会进一步比较问题和候选片段，把最相关的排在前面，最后只把少量高质量内容交给生成模型。

## RAG 的完整流程

```text
文档 -> 解析 -> 切分 -> Embedding -> 保存向量和元数据

问题 -> 问题 Embedding -> 初步检索 -> 权限过滤 -> 重排
     -> 相关片段 -> 模型生成答案
```

## 权限为什么必须提前过滤

不能先检索所有文档，再要求模型自行隐藏无权内容。模型可能把敏感信息带入回答，也可能在总结时泄漏。

正确做法是：检索时就根据当前用户的权限、部门和项目范围过滤数据，让无权文档根本不会进入模型上下文。

## RAG 和记忆的区别

知识库保存的是可供多人检索的外部资料，例如产品手册。记忆保存的是用户或任务的持续信息，例如“用户偏好简洁回答”。两者的数据来源、权限和更新方式不同。

## RAG 的常见失败原因

- 文档解析错误，表格内容丢失
- 切分破坏了标题和上下文
- 只用关键词，无法理解同义表达
- 找到了相关片段，但没有做权限过滤
- 检索结果太多，模型被无关内容干扰
- 没有要求模型基于证据回答

## 复习摘要

- RAG 是“先检索，再生成”。
- Embedding 把文本变成可比较的数字向量。
- 向量检索适合找语义相近的内容，混合检索通常更稳。
- 权限过滤必须发生在内容进入模型之前。
- RAG 的质量取决于文档处理、检索和生成三个环节。
