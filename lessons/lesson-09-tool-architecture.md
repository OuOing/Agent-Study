# 第 9 课：模型适配器、工具执行器与编排器

## 为什么要拆分

如果所有逻辑都写在一个函数里，接入真实模型、增加工具和处理错误都会很困难。常见的最小拆分是：

```text
模型适配器 -> 返回决策
工具执行器 -> 校验并执行工具
编排器     -> 组织循环、状态和异常
```

## 模型适配器

`model_decide` 是模型适配器的占位实现。它现在返回固定 JSON，未来可以替换为真实模型 API，而不改变任务接口和工具执行层。

模型适配器只负责：

- 组织上下文
- 调用模型
- 解析结构化输出
- 返回 `tool_call` 或 `final`

## 工具执行器

`execute_tool` 接收工具名称和参数，然后执行真实业务操作。它必须自己校验参数和权限，不能因为请求来自模型就跳过安全检查。

## 编排器

`run_agent` 是编排器。它把模型决策、工具结果和任务状态连接起来，并设置人工确认边界。

## 为什么模型不能直接执行 Python 函数

模型输出的是数据，不是具有系统权限的进程。后端可以在执行前检查：工具是否存在、参数是否合法、用户是否有权限、当前状态是否允许执行。

## 本课复习摘要

- 适配器隔离模型供应商变化。
- 执行器是权限和业务规则的边界。
- 编排器负责把多个步骤组织成可恢复的任务。
- 结构化决策至少应区分工具调用和最终回答。
