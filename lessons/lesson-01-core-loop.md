# 第 1 课：Agent 的基本运行机制

## 1. Agent 到底是什么

Agent 不是单纯的聊天窗口，也不是一个更长的 Prompt。它是一个围绕目标运行的应用程序：模型负责理解目标和判断下一步，程序负责调用工具、保存状态、执行动作并控制风险。

最简循环是：

```text
目标 -> 模型决策 -> 执行动作 -> 观察结果 -> 再决策 -> 完成
```

例如用户说“帮我整理今天的会议并创建待办”，Agent 可能需要读取会议记录、提取任务、生成草稿，最后在用户确认后写入任务系统。

## 2. Agent 与普通聊天的区别

普通聊天通常只有一次模型调用：

```text
用户输入 -> 模型 -> 文本
```

Agent 则包含状态和外部动作：

```text
用户目标
  -> 后端验证身份
  -> Agent 调用模型
  -> 模型选择工具
  -> 后端执行工具
  -> 结果返回模型
  -> 最终回答或继续执行
```

因此 Agent 的难点不只在模型能力，还在于权限、错误处理、数据一致性和用户体验。

## 3. 一个最小 Agent 的四个组成部分

### 模型

负责自然语言理解、信息抽取和下一步判断。模型可以建议做什么，但不应直接拥有系统权限。

### 工具

工具是模型可以请求应用程序执行的能力，例如查询数据库、搜索文档、发送邮件或创建任务。

### 状态

保存会话、任务进度、工具结果和错误。只保存聊天记录不够，因为长任务需要能够暂停和恢复。

### 编排器

编排器是后端代码，负责决定何时调用模型、何时执行工具、如何重试，以及何时要求人工确认。

## 4. 模型和代码如何分工

适合模型处理的事情：

- 判断用户意图
- 从会议纪要中提取任务
- 根据上下文选择查询工具
- 把结果总结成自然语言

必须由代码控制的事情：

- 用户身份和权限
- 金额、日期和业务规则计算
- 数据库写入和状态转换
- 工具参数校验
- 高风险动作审批
- 重试次数和超时

核心原则：模型处理不确定性，代码保证确定性。

## 5. Agent 的完整请求生命周期

1. 前端把用户目标发送给后端，并携带会话 ID。
2. 后端验证用户身份，加载必要的上下文和任务状态。
3. 编排器把目标、上下文和工具描述发送给模型。
4. 模型返回最终文本，或者返回一个结构化工具调用请求。
5. 后端校验工具参数和权限后执行工具。
6. 工具结果写入状态，并返回给模型判断下一步。
7. 达到完成条件后，后端把最终结果流式返回前端。

## 6. 为什么先学机制，再学框架

LangChain、LlamaIndex、LangGraph、AutoGen 等框架会帮助我们组织代码，但它们不会替我们解决业务权限、失败恢复和产品设计问题。理解底层循环后，才能知道框架中的节点、状态、工具和回调分别在解决什么。

## 7. 本课复习摘要

- Agent 是“模型 + 工具 + 状态 + 编排器”。
- Agent 的本质是决策、行动、观察的循环。
- 模型提出意图，后端决定是否执行。
- 生产可靠性主要来自代码、状态管理和权限控制。
